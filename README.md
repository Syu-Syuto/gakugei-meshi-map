# 学芸大めしマップ — MVP

東京学芸大学小金井キャンパス周辺の飲食店を探し、提案・審査するスマホ対応の独立Webサイトです。新規プロジェクトとして作成しました。既存リポジトリは変更していません。

**ソースリポジトリ・Webサイトともに一般公開。** 秘密鍵や投稿者情報は公開リポジトリに含めません。

公開サイト：https://syu-syuto.github.io/gakugei-meshi-map/

リポジトリ：https://github.com/Syu-Syuto/gakugei-meshi-map

Supabase・Turnstile・候補検索を設定済みです。本番の掲載店舗はまだ0件です。管理者本人によるログイン、投稿・写真・承認の通し確認は未完了です。運用手順と残る準備は `OPERATIONS.md` を参照してください。

## ローカルで試す

このフォルダーで Node.js 22以降を使い、次を実行します。追加パッケージのインストールは不要です。

```sh
node server.mjs
```

表示先： http://127.0.0.1:4173

設定が空の間はデモモードです。4店舗はすべて架空。投稿・承認はタブ内メモリーだけに保存し、再読み込みで消えます。デモ店舗はSupabaseに保存しません。デモの管理画面には認証がありません。本番はDBで管理者認証を必須にします。

操作例：検索 → 「お店を追加」 → URL解析または手入力 → 地図上で位置を指定 → 出典と確認メモ → 内容確認 → 投稿 → フッターの「管理」 → 歩行距離と経路記録 → 承認。

外部ネットワーク接続が必要な機能：Leaflet配信、OSM地図タイル、本番のSupabase、Turnstile。地図のライブラリが読み込めない場合も一覧・手動座標入力は利用可能です。

## 実装済み

- Leaflet + OpenStreetMapの地図、一覧、詳細。
- 店名・ジャンル、予算、徒歩距離の複合絞り込み。近い順・安い順。
- Google共有URLの文字列から店名候補を抽出。Googleへのページ取得・スクレイピング・API照会はしない。座標は転載しない。
- Supabase Edge Functionを通じた独立OSM候補検索。固定範囲のOverpass結果を24時間キャッシュし、入力文字列はクエリに埋め込まない。
- 候補選択、手入力、地図指定、投稿者確認。短縮URL・店名を含まないURLは手入力に誘導する。
- 匿名サインイン（登録不要）＋Turnstile、投稿受付RPC、審査待ち一覧、管理者ログイン、承認・却下。
- 承認時の重複チェック、トランザクション、投稿所有者・状態の偽装防止、RLS。
- GitHub Pages用ワークフロー。公開ファイルだけを配置し、SQL・手順書・テストは配信対象に含めない。

## Supabaseの初期設定

既存データのない専用の新規プロジェクトを使います。接続前のアプリに実店舗はありません。

1. SQL Editorで `supabase/migrations/` の001〜005を番号順に各1回実行します。
2. Authで匿名サインインを有効にし、Cloudflare TurnstileのCAPTCHA保護を有効にします。Turnstileの秘密鍵はSupabase Auth設定だけに保存します。本番ドメインをTurnstile側の許可ホストに登録します。
3. 管理者の通常アカウントをSupabase管理画面で作成し、公開サインアップによる通常アカウントの作成を制限します。ユーザーIDを次のSQLに設定し、管理者を登録します。匿名ユーザーを管理者にしないでください。

```sql
insert into public.admins(user_id) values ('管理者のauth.users.idをUUIDで指定');
```

4. `config.js` にプロジェクトURL・publishable key（またはanon key）・Turnstile site keyを設定します。これらはブラウザーで公開される値です。**service_role / secret keyを置かないでください。** AuthのSite URLは公開サイトURLにします。
5. Supabase CLIでEdge Functionをデプロイします。プロジェクトの連携・認証は自分の環境で行います。

```sh
supabase link --project-ref YOUR_PROJECT_REF
supabase secrets set ALLOWED_ORIGIN=https://YOUR_ACCOUNT.github.io
supabase secrets set OSM_USER_AGENT="GakugeiMeshiMap/0.1 (https://YOUR_ACCOUNT.github.io/YOUR_REPO/)"
supabase functions deploy osm-candidates
```

`ALLOWED_ORIGIN` はパスなし・末尾スラッシュなしのOriginです。独自ドメイン利用時はそのOriginにします。ローカル動作確認時だけ `http://127.0.0.1:4173` に変更し、公開前に戻します。`SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` はEdge Functionの実行環境が提供する値を使い、フロントには渡しません。`verify_jwt=false` は認証省略ではなく、関数内で `auth.getUser(token)` を実行するためです。

`OVERPASS_URL` は任意の管理者設定。既定値は `https://overpass-api.de/api/interpreter` です。利用条件に合わせた運用者情報をUser-Agentに設定してください。検索には匿名認証とCAPTCHA完了が必要です。候補なし・サービス障害時も手入力投稿を続行できます。

## GitHub Pagesへの公開

公開リポジトリを使います。設定手順だけを用意しており、リポジトリ作成・公開はまだしていません。

1. GitHubで**公開（Public）**の新規リポジトリを作成します。
2. このフォルダーの内容をリポジトリ直下に配置します。`index.html` が直下にある状態にします。
3. Settings → Pages → SourceをGitHub Actionsに設定します。
4. `main` にpushするとテスト後に公開用ファイルだけを配置します。相対パスを使用しているため、`/リポジトリ名/` 配下でも動作します。
5. 公開サイトでは閲覧者が画面のHTML・CSS・JavaScript・公開設定値を参照できます。公開リポジトリではソースコードも閲覧可能です。秘密鍵・審査データはSupabase側に置きます。

参考： https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages

## 徒歩25分の扱い

直線距離を徒歩時間と表示しません。管理者が**実際に通行可能なキャンパスの入口を起点にした歩行経路**を確認し、歩行距離・入口・経路・確認日・根拠を入力して承認します。表示は80m/分換算で切り上げ。最大2,000mを25分の目安とします。信号待ち、開門時間、個人差は含めません。

`config.campus` は地図中心の暫定値で、経路計算の起点ではありません。運用開始時に正門など統一の入口を決め、経路記録の基準を揃えてください。自動の歩行ルーティングは未実装です。OSM検索の矩形は候補を探すための広めの範囲で、掲載範囲を保証しません。

## データの出典とライセンス

Google共有URLは投稿者が指定した外部リンクとしてのみ保存し、管理者承認後に公開します。URLから読んだ店名ヒントを掲載情報へ自動転記しません。Googleの説明文・レビュー・写真・営業時間・座標を取得しません。短縮URLのリダイレクト展開も行いません。店舗名・座標はOSM候補、店舗公式情報、投稿者の独自確認・地図指定で入力し、管理者が別途確認します。

OSM店舗候補にはOSMオブジェクトURLを保持し、画面に © OpenStreetMap contributors とODbLを表示します。公開店舗データベースはODbL 1.0で提供し、フッターの「店舗データ（ODbL）」から公開全件をJSONで取得できます。投稿フォームにもODbLでの公開への同意を含めています。独自情報とOSM由来情報はsource_kind/source_urlで区別します。サイトのプログラム自体へのオープンソースライセンス付与は行っていません。

OSMタイルはHTTPS・常時見える帰属表示・通常のブラウザーキャッシュを使います。先読み・一括取得・オフラインキャッシュ・Refererの抑止は行いません。タイルにSLAはありません。アクセス増加時は利用条件を確認して配信事業者へ切り替えます。`config.tileUrl` の変更時は帰属表示も提供元に合わせて変更してください。

- https://operations.osmfoundation.org/policies/tiles/
- https://www.openstreetmap.org/copyright
- https://opendatacommons.org/licenses/odbl/1-0/
- https://wiki.openstreetmap.org/wiki/Overpass_API
- https://supabase.com/docs/guides/auth/auth-anonymous

Nominatimの公共APIは利用しません。候補検索はボタン操作でのみ実行し、入力ごとの外部検索や一括ジオコーディングは行いません。

## サーバーを自分で運用する必要はありません

投稿の受け取り先はSupabaseが運用するデータベースです。サイト公開は静的ホスティング、認証・保存・承認処理とOSM検索はSupabaseに任せます。自分のPCをつけっぱなしにする必要も、VPSを借りる必要もありません。ローカル確認用の `server.mjs` は開発時だけ使うもので、公開サイトの受け取りサーバーではありません。

GoogleフォームもGoogle側のサーバーへ保存する仕組みなので、サーバーが不要になるわけではありません。今回の候補確認・地図指定・審査からの公開を一体化するには、現在の方式が適しています。Googleフォームへの切替えはしていません。

Supabaseには無料プランがありますが、利用量に上限があり、非アクティブな無料プロジェクトは停止対象です。開始時点の運用は無料枠内を目指し、規模に応じて見直します。有料プランへの変更・契約は行っていません。最新条件： https://supabase.com/pricing

## セキュリティと審査

一般閲覧者は公開店舗のみ取得できます。投稿の作成は匿名認証済みを含むauthenticatedに許可したRPCを通します。直接INSERT/UPDATE/DELETEは禁止。投稿者は自分の投稿だけ、管理者はすべての投稿を読めます。adminsテーブルはクライアントから読み書きできません。管理者判定にユーザー編集可能なメタデータを使いません。

投稿は1ユーザー1分に1件・24時間に5件。OSM候補検索は1ユーザー1時間20回。Overpassへのキャッシュ更新は全体1時間1回までです。CAPTCHAはSupabase Auth側でも有効にし、画面だけの確認にしないでください。匿名IDを作り直す攻撃への追加対策として、公開前にAuthのIPレート制限・利用量上限・通知を設定します。必要に応じて投稿経路へ追加のEdge側CAPTCHA検証を導入します。

承認RPCは管理者権限を検証し、投稿の行ロックとトランザクション内で公開します。OSM IDの重複と同名・近隣の重複を拒否します。表記揺れの重複は管理者確認が必要です。店名・メモ等はtextContentで表示し、利用者のHTMLを実行しません。出典URLはHTTPSなどを検証しますが、外部リンクの内容まで安全性を保証しないため、管理者はドメインを確認して開いてください。

審査では営業継続・名前・住所/位置・予算・出典・重複・経路に加え、個人情報・誹謗中傷・転載・広告を確認します。投稿メモと経路メモは承認後に公開されます。却下理由、投稿者ID、管理者IDは公開店舗テーブルに含めません。

運用開始前に連絡窓口、削除/訂正依頼、プライバシー表示、データ保持期間を決めて掲載してください。公開店舗の訂正・非公開化UIは次期対応です。MVPでは管理者がSupabase SQL Editorで対象店舗を修正・削除します。投稿履歴参照があるため削除前に参照関係を確認してください。

定期メンテナンス案：古いapi_limitsを7日で削除、却下投稿は決めた保持期間で削除、不要な匿名Authユーザーは投稿との参照を確認して整理、DBバックアップ、管理者のアクセス監査。自動ジョブはまだ登録していません。

## 予算・自転車・駐輪情報

予算は1人分の目安を700円程度・1,000円程度・1,500円程度から選びます。不明も選択可能です。検索は価格上限ではなく、選んだ区分に一致するお店を表示します。新しいbudget_yenを使い、旧price_yenは履歴として保持します。既存価格が3区分と一致しない場合に勝手な推測で割り振りません。

自転車検索は、確認済み歩行経路距離を200m/分で割り、分単位に切り上げた参考値です。走行可能な経路、信号待ち、駐輪時間、坂道を検証した自転車ルートではありません。掲載対象は引き続き徒歩約25分以内です。

駐輪可・駐輪不可・不明と、駐輪場所や条件の補足を投稿できます。管理者の確認後に公開し、一覧・詳細・検索に反映します。不明を駐輪可に含めません。路上への駐輪許可を意味せず、店舗の指定場所・利用条件を確認してください。

既存のSupabaseプロジェクトでは未適用の番号以降だけを順に適用してください。001・002適用済みなら003〜005を追加適用します。

## 店舗リンクとおすすめ

Googleマップの店舗URL・公式サイトURLを任意で投稿できます。リンク先を取得したり、Googleの店舗データをコピーしたりはしません。承認後の詳細画面から別タブで開きます。GoogleマップURLがなければ、店名・住所の検索URLを作り「Googleマップで探す」と明示します。公式サイトは登録がある場合のみ表示し、店舗の公式サイトか管理者が確認します。店舗ページ未登録と特定の店舗ページへのリンクは区別します。

おすすめメニュー（100文字以内）、その値段（0〜100,000円の整数、未確認なら空欄）、推しポイント（100文字以内）は任意です。メニュー価格は大まかな予算区分とは別の情報です。価格だけの投稿はできません。管理者の承認後に「投稿者のおすすめ」として掲載します。投稿時点の情報であることを表示し、転載・個人情報・誹謗中傷等も審査します。今のMVPは店舗登録時のおすすめを保持する仕様で、複数投稿者のおすすめ一覧や既存店舗への追加投稿は次期対応です。

## 目的検索と写真投稿

目的は「普段の食事・打ち上げ・新歓・少人数の集まり」の複数選択です。目的別に検索でき、詳細には人数の目安・予約条件などの補足（250文字以内）を表示します。タグは団体受入・貸切・飲酒の可否を保証するものではありません。新歓・打ち上げの人数、貸切、予約、予算などを管理者が確認してから掲載し、利用者にも予約前の確認を案内します。

写真は店舗登録時に任意で1枚。自分で撮影し、人物・個人情報・店内撮影ルール等の必要な確認を済ませた写真に限定する同意欄を設けています。Googleなどの写真転載は不可です。元画像はJPEG/PNG/WebP・10MB以下、ブラウザーで長辺最大1600pxのJPEGへ再描画し、3MB以下にして送ります。通常の画面経由では元画像のEXIFを引き継ぎません。HEIC・SVGは非対応です。加工処理を回避した直接API投稿の内容までは自動判定しないため、管理者は画像内容・権利・個人情報を目視審査します。

005の適用でprivateなrestaurant-photosバケットと権限制御を作成します。本番では写真の実体をGitHubへ保存しません。既存の広範なStorageポリシーがない専用Supabaseプロジェクトを使います。アップロード予約RPCは1ユーザー24時間に5回まで（失敗分も含む）、予約から1時間以内だけアップロード可能です。ランダムUUIDのファイル名を使い、公開されるパスに投稿者ID・元のファイル名を含めません。既存パスへの上書き・クライアントからの削除は許可しません。

審査前の写真は投稿者本人と管理者だけが閲覧可能。公開店舗に紐づいた承認済み写真だけ、一般閲覧者が取得できます。privateバケットから5分間の署名URLで表示します。削除・非公開化後も発行済みURLは期限まで有効になり得るため、緊急削除ではStorage側の実体も管理者が削除してください。写真の著作権は撮影者に残り、サイト掲載への許諾として扱います。店舗DBのODbL表記は写真自体へのライセンス付与を意味しません。

未使用アップロード・却下写真の整理は、管理者がStorage API/管理画面経由で行います。StorageのメタデータだけをSQL削除しないでください。例：30日超の未使用/却下写真を、公開店舗・審査中投稿で参照されていないことを確認して削除。予約レコードは日次制限と参照関係を確認して整理。自動削除ジョブはまだ登録していません。公開前に保持期間、削除窓口、利用量通知を決めてください。容量・配信量はSupabaseの利用枠に含まれます。

参考： https://supabase.com/docs/guides/storage/buckets/fundamentals 、 https://supabase.com/docs/guides/storage/security/access-control

ローカルデモは画像をタブ内メモリーにだけ保持します。再読み込みで消えます。実Supabaseのアップロード・署名URL・画像配信は未接続のため、公開前に実接続で確認が必要です。
